# CupNavi – 20 Critical User Journeys

These are the product flows that should become the permanent regression guard.

1. Create a tournament and persist its basic settings.
2. Switch active tournament and remain on the selected tournament after rerun.
3. Open a tournament from a direct public cup/slug link.
4. Add teams up to configured capacity.
5. Create/manage competition classes and groups.
6. Generate a valid schedule from configured constraints.
7. Recover/regenerate a dirty schedule without corrupting existing data.
8. Assign pitches and referees.
9. Publish a tournament and expose the correct public view.
10. View public schedule/results filtered by team/group/pitch.
11. Report a match result and persist it.
12. Report match events without exceeding result constraints.
13. Update standings/statistics from completed match data.
14. Resolve and display playoff progression/bracket.
15. Team leader signs in and accesses only the correct team.
16. Match reporter signs in and accesses only reporting functions.
17. Send/read team-targeted messages with correct authorization.
18. Backup tournament data and restore/recover without data loss.
19. Complete/archive a tournament and retain history.
20. Admin explicitly deletes an intended tournament with confirmation while other tournaments remain intact.
